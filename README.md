# InsureFlow

InsureFlow is a broker-led insurance orchestration platform. It lets customers apply for insurance, compare provider-generated quotes, select add-ons, complete payment through a third-party gateway, and receive issued policy documents.

The customer flow is intentionally simple:

```txt
Visit app
→ Select insurance type
→ Fill application without login
→ Get quotes
→ Select plan and add-ons
→ Pay
→ Policy issued after successful payment
→ View policy, receipt, and support status from dashboard
```

Broker registration is not part of the customer journey. Brokers are registered by an InsureFlow admin using an admin-protected API. The Provider Backend generates and stores the broker API key hash.

## System Overview

```txt
Frontend
  Customer UI + Admin UI

Main Backend
  Customer journey, application, transaction ledger, normalized quotes,
  dashboard, admin operations, support, audit, and provider sync.

Provider Backend
  Provider setup, broker API-key registry, plan/add-on catalog,
  quote generation, payment session creation, payment verification,
  policy issuance, documents, and webhook retries.

Payment Gateway
  Razorpay or similar checkout provider for UPI, card, netbanking,
  wallet, and EMI payments.
```

## Core Rules

- Customer does not select a broker.
- Admin registers brokers.
- Broker API key is generated by the system, shown once, and stored only as a hash.
- Quotes are generated by Provider Backend.
- Main Backend stores normalized quotes.
- Main Backend must not generate payment URL/order.
- Provider Backend creates payment session/order.
- Policy is generated only after verified payment success.
- Transaction is the central ledger in Main Backend.
- Provider Backend also has a provider-side transaction linked to the Main transaction.
- Insurance-specific data lives in `insurance_details`, linked to transaction.

## Main Customer Flow

```txt
Frontend
→ POST /api/v1/applications
→ Main Backend creates application, transaction, insurance_details
→ Main Backend calls Provider Backend for quotes
→ Provider Backend creates provider_transaction and provider_quotes
→ Main Backend stores normalized quotes
→ Frontend displays quotes
→ User selects quote and add-ons
→ Main Backend updates transaction
→ User clicks Pay
→ Main Backend requests payment session from Provider Backend
→ Provider Backend creates gateway order/session
→ Frontend opens payment checkout
→ Provider verifies payment
→ Provider generates policy
→ Provider syncs payment/policy status to Main Backend
```
